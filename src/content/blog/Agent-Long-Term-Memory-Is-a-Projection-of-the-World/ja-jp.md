二年前、Agent に「焼肉が大好きなんだ」と話した。先月は「ベジタリアンになったよ」と言い直した。そして今日、チームの食事会の店を探してほしいと頼んだら、Agent は自信満々にシュラスコの店を予約してきた。

たいていの人は、まずモデルが馬鹿になったと思うだろう。でも、これはモデルのせいではない。悪いのは、その下にある記憶の仕組みのほうだ。

いま世に出ている Agent の記憶は、どれも似たり寄ったりだ。話した内容を細かく切ってベクトルに変換し、片っ端からベクトルデータベースに放り込む。思い出す段になったら、目の前の質問との意味的な類似度を計算して、いちばん近い数件を拾い、モデルに渡す。ところが、ベクトル空間には遠い近いしかない。前後関係もなければ因果もないし、「新しい発言が古い発言に取って代わる」という発想にいたっては影も形もない。「焼肉が好き」も「ベジタリアンになった」も一緒に拾われ、二つの点は同格に並ぶ。どちらがまだ有効なのか見分けがつかないので、システムは「レストラン」に近いほうをあっさり選んでしまう。

これはせいぜい検索機能つきのチャットログ置き場であって、とても記憶とは呼べない。記憶は保存ではないし、検索でもない。

Ankole は、私がいま作っているオープンソースのプロジェクトだ。企業向けの Agent Harness で、その中心にはデジタル社員のための Company Brain、つまり「会社の頭脳」がある。この頭脳にどうものを覚えさせるか。ここしばらく、時間の大半をそれを考えることに費やしてきた。考えれば考えるほど、確信は深まっていく。Agent の長期記憶は会話ログの積み重ねであってはならない。証拠が入るたびに推論し直し、修正し続ける「世界の投影」であるべきだ。

## 記憶は「しまう」ものではなく「導き出す」もの

バックエンドを書いたことがある人なら、イベントソーシング（Event Sourcing）はおなじみだろう。この方式では、データベースに残すのは追記専用のイベントログだけで、最終状態そのものは持たない。口座の残高がいくらか、注文がどの段階にあるかは、ログを再生して導き出す。そうして導き出したビューを、プロジェクション（Projection）、つまり投影と呼ぶ。

人の記憶も同じ理屈で動いている。人間の脳は、もともと録画装置ではない。思い出すたびに、いま手元にある手がかりを頼りに、過去の断片を組み立て直している。長年一緒に働いてきた相棒の印象にしても、会うたびの録画を頭にしまってあるわけではない。「この人はこういう人だ」という見立てがあって、相手が何か新しいことをするたびに少しずつ手直ししているだけだ。いちいち録画を見返す人などいない。

Agent の記憶も二層に分けるべきだ。下の層は証拠である。誰がいつ何を言ったか、どの決算資料を読んだか、どのニュースを拾ったか。追記するだけで書き換えず、いつでもさかのぼって確かめられる。上の層は認識、つまり世界の投影だ。証拠の山から導いた、いまの判断である。この人はいまも肉を食べるのか。あの会社はサプライチェーンを組み替えている最中なのか。新しい証拠が来れば、古い認識は手直しされるか、ひっくり返される。

チャットログを溜めるだけのシステムは、推論の重荷をすべて、質問された瞬間のモデルに背負わせている。その瞬間、モデルに見えているのは、検索で拾われた断片が数件だけだ。時系列も見えなければ、因果もたどれない。これで間違えないほうがおかしい。ベクトル検索は探すだけ。記憶は推論してはじめてできあがる。

## 世界はこちらが口を開くのを待ってくれない

Agent の記憶をめぐる議論は、たいてい人と AI の会話のまわりをぐるぐる回っている。チャットからユーザーの好みやフィードバック、期待をつかみ、エンジニアリングの工夫でモデルが使えるコンテキストをほぼ無限まで広げる。OpenViking のような取り組みも、このあたりはどこも似たようなものだ。もちろん役には立つ。だが、まるで足りない。

LLM の知識はある時点で止まっていて、それ以降に世界で起きたことをモデルは何ひとつ知らない。「なら検索エンジンをつなげばいいのでは」と思うかもしれない。そう単純な話ではない。従来の RAG には死角がある。何が重要かを知らなければ、何を検索すべきかもわからないのだ。原油先物を調べる場面を考えてみよう。米国とイランのあいだで戦争が始まったことを知らなければ、システムが自分から「ホルムズ海峡」を検索しにいくことは決してない。この背景がない限り、検索エンジンが手元にあってもただの飾りだ。

駆け出しのアナリストも十年選手のベテランも、使っているのは同じ Google、同じ Bloomberg 端末だ。ベテランが違うのは、頭の中に生きた世界地図を持っていることだ。どの会社とどの会社が川上と川下でつながっているか、タンカーがどの海峡を抜けていくか、中央銀行の利下げがどんな経路でどのセクターに波及するか。どこを見るべきかは、この地図が教えてくれる。

だから Agent の記憶には、同じ重みを持つ二本の入力経路が要る。一本は会話だ。人の話を聞いて、意図や習慣をつかむ。もう一本はイベントだ。政策の変更、決算の発表、価格の急変、業界再編といった外の世界の動きに目を光らせる。中央銀行が利下げを発表したら、グループチャットで誰ひとり話題にしなくても、関連する資産に対する Agent の認識は更新されるべきだ。頼まれれば、本を一冊じっくり読み込んだり、数十ページのアナリストレポートを読み通したりして、学んだことを記憶として消化できなければならない。

世界の投影は世界そのものではないし、ましてや杓子定規なログの保管庫でもない。それは Agent がいま持っている認知モデルのことだ。新しい証拠が来れば、古い認識を補い、正し、あるいは入れ替える。忘却、剪定、帰納、統合によって、このモデルをできるだけ今の世界に寄り添わせておく。関係のグラフはその一部にすぎず、事実とその時間的な移り変わりもあわせて整理しなければならない。

## なぜグラフなのか、それも制約つきのグラフなのか

では、この投影はどんな形をしているのか。答えはグラフだ。

ベクトル検索の弱点は、情報を細かく切り刻みすぎることにある。「サーモン」「ウニ」「寿司」をベクトルデータベースに入れても、高次元空間に浮かぶ三つの孤立した点になるだけだ。幾何学的な距離では、これを「この人は和食派だ」とまとめられないし、点と点のあいだに矢印を引いて「ベジタリアン」が「焼肉」に取って代わったと示すこともできない。記憶に求められる抽出、進化、矛盾の検出は、どれも関係を扱う作業だ。ベクトルは点にすぎない。ネットワークになれるのはグラフだけだ。

グラフ上なら、「原油」と「米イラン戦争」が一本の辺で直接つながっている。Agent が原油を調べれば、関連する出来事がその辺をたどって自然と浮かび上がってくる。検索語を当てずっぽうで探る必要はない。

ただし、グラフは好き勝手につないでいいものではない。GraphRAG は、テキストの中で一緒に出てくる実体を抜き出すだけで、型の制約がない。ふつうのグラフデータベースなら、「トヨタはピザが好き」という辺だって難なく張れてしまうし、データベースは止めてくれない。モデルに自由に抽出させれば、幻覚が生んだこの手のでたらめな関係が、雑草のようにはびこる。

この点で、Palantir のオントロジー（Ontology）からは大きなヒントをもらった。関係にはルールを課す、ということだ。まず、世界にどんな種類の実体があるかを決める。会社、指数、イベント、人物といった具合だ。次に、どの種類とどの種類のあいだに、どんな関係を張ってよいかを決めてしまう。たとえば「含む」という関係は、指数から会社に向かってしか張れない。こうした型つきの骨格があってはじめて、モデルは抽出のときにむやみに線を引かなくなる。

とはいえ、純粋なオントロジーにも致命的な弱点がある。明示的に宣言された事実しか収められず、推論から導かれ、いまも変わり続けている判断は入らない。正確ではあるが、死んでいる。オントロジーは骨格で、世界がどんな実体と関係でできているかを定める。推論で得た記憶は肉で、その骨格の上でいま何が起きていて、それが何を意味するかを担う。肉のない骨格は死んだ知識ベースであり、骨格のない肉はまとまりのない記憶の断片にすぎない。

それでも、私と Palantir とで根本的に考えが分かれるところが一つある。Palantir のオントロジーは、あらかじめ上から設計されている。だが、Agent の目に映る世界は下から育っていくものでなければならない。ビジネスは絶えず変わる。今日は「会社」と「指数」だけ追えば足りても、明日には「地政学的な政策」や「サプライチェーンのボトルネック」が顔を出す。すべての型をアーキテクトが考え抜くまで待っていたら、システムは動き出す前に固まってしまう。私のやり方は、上から始めて下から進化させることだ。まずは最小限の汎用的な型で動かし、新しい概念が出てきたらタグをつけておく。ある概念が何度も現れて証拠が十分に貯まったら、システムが正式な型への昇格を提案し、人が承認する。忘却、剪定、帰納、統合を通じて、このオントロジーは少しずつ形を変えていく。

## 多視点：誰が誰をどう見て、誰がその場にいて、誰に話せるのか

同僚の目に映るあなた、親の目に映るあなた、自分の目に映るあなたは、まるで別物の三つの像だ。それぞれに来歴があり、互いに矛盾することもあるが、どれもそれなりに筋は通っている。Agent の記憶もそうあるべきだ。同じ実体について、誰がどう見ているかを分けて覚えておく。

一人のユーザーを相手にするアシスタントなら、この問題はまだ目立たない。ところが企業のグループチャットに入った途端、話は一気にややこしくなる。一つのグループに何人もの人と何体ものデジタル社員がいて、情報は多対多で行き交う。システムは「この Agent はこのユーザーについて何を覚えているか」に答えるだけでは足りない。グループの中で誰が誰に何を言ったか、どの認識をみんなで共有していて、どれが一部の人だけのものかを、きちんと区別しなければならない。

山田さんがグループチャットで「田中さんって当てにならないよね」とこぼしたとしよう。記憶システムが「田中さんは当てにならない」とそのまま保存してしまえば、一人の見方が組織全体の事実になり、田中さんはシステムの中でいわれなく悪者にされる。だから、認識の一つひとつには、次の二つを必ず結びつけておく。

- **事実なのか、判断なのか。** 「第4四半期の売上高が15%増えた」は検証できる事実だ。「海外事業が収穫期に入った」は判断である。判断が当たっていたかどうかは、時間が経たないとわからない。白黒がついたら振り返って、誰の見立てが当たっていたのかを確かめる。
- **誰の判断なのか。** 「田中さんは当てにならない」を田中さんの側に貼りつけてはいけない。山田さんの名義で記録する。ある時点で山田さんがそう思っていた、ということだ。

私がグループチャットをいちばん大事な場面だと考えているのは、会社にとって最も価値のある財産が、たいていどこにも書かれていないからだ。どの部署が本当に決定権を握っているのか、どの取引先には特定の中間管理職を通さずに当たらなければならないのか、どの指標が見栄えはいいのに水増しされているのか。この手の暗黙知は日々のやり取りの中に散らばっていて、組織が大きくなるほどその傾向は強まる。大企業のリストラがしばしば大動脈を切ってしまうのはこのためだ。失われるのは、その職務の生産性というより、その人の頭の中にあった、誰も書き残していない人間関係の地図まるごとなのである。

視点の問題は、もっと現実的な防衛線にもつながる。誰の前で何を話してよいか、という問題だ。Agent は AI の同僚であって、誰か一人の伝言係ではない。人間の同僚と同じルールに従う。ある知識を知ってよいのは誰かは、その知識自身が持つ公開範囲で決まる。そして Agent は口を開く前に、いま誰がその場にいるかも確かめる。社内の人間だけなら話してよいことでも、グループに外部のコンサルタントが加わったら、ぐっと飲み込まなければならない。知識は組織に帰属し、特定の Agent に縛られない。いつかどこかのデジタル社員が引退しても、組織の記憶まで一緒に持ち去られることはない。

## 夢と忘却

ログが増える一方なら、システムは遅かれ早かれ些末な情報に埋もれてしまう。私の考えでは、忘れられることそれ自体が、人の知性の重要な一部だ。あらゆる情報がいつまでも同じ重みを持ち続ければ、本当に大事なことはかえって底に沈み、Agent の世界の投影もどんどん歪んでいく。

記憶が自分で新陳代謝できるように、私は Dreaming というオフラインのバッチ処理を組み込んだ。名前の由来は、人が眠っているあいだに見る夢だ。昼間の経験を、夜のうちに整理する。やることは三つある。

- **帰納と演繹。** ばらばらの観察をまとめて、一段上へと推し進める。記憶に「サーモンが好き」「マグロが好き」とあれば、システムは「この人はどうやら和食派らしい」という一文を引き出し、根拠を添える。ただしこれは推測であって事実ではない。のちの証拠が裏づけることもあれば、修正したり、ひっくり返したりすることもある。演繹のほうは、既存の事実、ルール、関係から、いま手元のタスクに役立つ結論を導く。長く使えそうな結論は、記憶に書き戻す。
- **矛盾をほどく。** ユーザーが引っ越したなら、「ニューヨーク在住」は「2019年から2024年まではニューヨーク、2024年からはシアトル在住」へと書き換わっていくべきだ。食い違う二つの記録を並べたままにはできないし、新しいほうで古いほうを上書きして済ませるわけにもいかない。本当に判断のつかない食い違いは、システムがこっそり書き換えたりせず、整理して人の前に差し出し、判断を仰ぐ。
- **段階的な忘却。** 忘れるといっても、物理的に消すわけではない。重みを下げ、熱を冷まし、ふだんの想起から外していくのだ。出来事は週単位で、好みは月単位で、事実は年単位で薄れていく。二年前の「焼肉が大好き」はとっくに冷めきっていて、先月の「ベジタリアンになった」はまだ湯気を立てている。この減衰の仕組みだけで、Agent が例のシュラスコの店を予約することは二度とない。

## 全体像

まとめると、だいたいこうなる。

```text
会話とグループチャット · ニュース、論文、Webページ、データ · 外部イベント
          │
          ▼  学習：主張として抽出し、出典・時刻・誰の見方か・誰が知ってよいかを記録
実体 · 事実 · 判断 · タイムライン · 関係（オントロジー）
          │  ▲
          │  └─ Dreaming：帰納・演繹・忘却・剪定・統合、オントロジーの進化
          ▼
想起：全文検索 + ベクトル + 関係をたどった展開
          │
          ▼  質問者が知ってよいものだけを取り、その場の全員が聞いてよいことだけを話す
        Agent
```

## おわりに

つまるところ、大規模言語モデルがいちばん得意なのは推論であって、丸暗記ではない。人間は深く考えると疲れるし、疲労や先入観や感情に流されやすい。モデルにはそうした重荷がない。前提さえ十分に与えれば、疲れ知らずに、一貫して推論を進めていける。Agent の記憶は、人間の生物学的な限界を越えられる。たくさん覚えることによってではなく、より深く推論することによって。

ここに書いた設計は、すべて Ankole の Company Brain に入っている。コードは完全にオープンソースで、記憶をどう蓄えるか、推論をどう回すか、Dreaming がどう夢を見るかまで、GitHub の [AgentBull/ankole](https://github.com/AgentBull/ankole) でのぞいてみてほしい。道のりはまだ長い。一緒に手を入れてもらえたらうれしい。
