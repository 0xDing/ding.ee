大语言模型聊天很厉害，但在真实的软件系统里拿它当分支判断用，体验其实非常差。

做 Ankole 数字员工系统这一年多，我被这类场景折磨过无数次：让 Agent 处理一个网页操作或者分派一张工单，系统必须先知道“当前按钮能不能点”或者“这封邮件该不该转给风控”。为了拿到一个简单的布尔值或分类标签，现有的做法是把整个上下文扔给一个几十上百亿参数的模型，等它在上下文里自回归地吐出几百个 Token 的思维链，最后在末尾解析出一个脆弱的 JSON。

耗时两三秒，账单多算几千个 Token，中间只要格式稍微抖动一下，下游解析直接报错。

这件事从物理机制上就很别扭。人类在做日常决断时，从来不需要在脑子里把推导理由一句一句念出声来。急诊科医生看心电图、老司机在十字路口并线、下快棋的棋手落子，都是瞬间完成的。卡尼曼把这个叫“系统一”——依赖长期的经验沉淀，直接在感知层完成模式识别，不经过显式的语言中介。

TypeSafe 前阵子发了 Jev，正式把这类模型称为 System One，这个方向的切入点是对的。但在实现路线和开源生态的发展上，我和目前主流的做法有很大的分歧。

开源社区这几个月冒出了一大堆复现 Jev 的项目，做法几乎清一色是拿 Qwen 这类 Decoder-only 因果模型挂个 LoRA，然后在 Prompt 里写“请在 A、B、C 中选择”，推理时去截取首个 Token 位置对应字母的 Logit 算概率。

这类方案我搭过、测过，结论是根本走不通。

首先是**先验污染**。因果模型在预训练时，词表里的不同字母本身就带强烈的概率偏好；选项排在前面还是后面，模型的输出差异极大。靠后验的温度调节根本抹不平这个底色。

更根本的问题是**计算形态的错配**。决策任务的数据形状是不对称的：

作为证据的状态（一份数千字的合同、系统的调用栈、网页 DOM 树）通常很长，而且每个字都需要和上下文互相参考；而针对这份证据要问的问题，往往有几个甚至几十个，每个问题本身都很短。

拿因果语言模型去读长状态，单向因果掩码等于强制它从左往右戴着眼罩看代码，前面的 Token 根本感知不到后面的信息。而且就算给状态做前缀缓存（Prefix Caching），面对同一个状态并行发起的多个问题，Decoder 的自注意力计算依然无法省掉。

所以做 **Bongard** 时，我完全避开了 Decoder-only 架构，选了被大多数人忽视的 Encoder–Decoder（底座基于 `T5Gemma 2 4B-4B`）。

这套拓扑结构的意图非常直接：

几千个 Token 的状态只进一次双向 Encoder，把全景上下文彻底编码成致密的 Key-Value 缓存；针对这个状态提出的 $N$ 个具体问题，在 Decoder 里分头推进，直接共享 Encoder 吐出来的状态。而在 Decoder 的尾端，我挂了一个只有 130 万参数的双线性判决头（Bilinear Head），直接读取候选隐藏状态与全局决策状态的乘积，一步 Softmax 映射出概率。

**整个推理过程不生成哪怕一个 Token。**

这使得对同一个长状态连续做 32 次判定时，Bongard 只需要 221 毫秒（单次决断约 6.9 毫秒），显卡算力开销折算下来每百万次判定大约 4.4 美元。更重要的是，Encoder 的双向感知让模型在读表格、读代码时不再有盲区——我们做过对比消融，如果把 Encoder 强行改成单向因果掩码，下游决断的准确率会瞬间跌掉 5 个百分点，负对数似然（NLL）直接恶化四倍。

架构定下来之后，真正的硬仗在训练。

做不吐字的模型，最大的坑是**隐藏层表征的塌陷**。

常规的监督微调（SFT）只能教模型把特定的题目选对，教不出鲁棒的语义理解。模型非常容易抄捷径：看哪个选项长就选哪个，或者死记某种特定的提问句式。只要把同一个问题换一种措辞，输出的概率就剧烈晃动。

为了让模型学会跨表述的“语义不变性”，最理想的路径是走 Yann LeCun 的 JEPA（联合嵌入预测架构）思路：不预测具体的字词，而在隐藏层让语义等价的状态去相互预测。

但在动手做第二阶段（Stage 2）的时候，我们遇到了一个教科书上没写的大坑。

在普通语言模型里做表征对齐，背后有“预测下一个词”这个任务在兜底。26 万词表的 Next-token Loss 是一根强有力的锚，死死扯住底层的隐藏状态不让它乱飘。但 Bongard 是个完全不吐字的模型。当我们尝试用常规的余弦相似度拉近同义文本时，跑出来的指标非常诡异：**在模型深处，两段风马牛不相及的随机文本，隐藏状态的原始余弦相似度竟然常年维持在 0.99 左右。**

这是极端的高维各向异性（Anisotropy）——所有向量挤在一个极窄的圆锥体里。如果直接对它们做 Cosine Loss，梯度几乎全在把所有向量往同一个方向挤，模型瞬间失去区分度。

为了在没有词表锚点的情况下把表征拉开，我们在批次内做了去中心化（Pack Centering）：每个训练批次先算出全部样本隐藏状态的均值强行扣除，剔除掉那个虚高的全局偏移。同时，对于一道选择题，把题目的决策状态当成锚点，去对比“正确选项为真”与“错误选项为假”的事件状态。因为正反事件共用了同一份证据和提示词模板，它们相减时，模板本身的字符指纹会被完全对消，最后留在梯度里的，只剩区分对错的核心流向。

把表征洗干净之后，模型在完全没见过的改写问题上的准确率从 75.7% 提升到了 85.9%，因句式变化带来的概率方差基本被抚平了。

到了第三阶段（Stage 3），问题变成了**概率校准**。

很多用强化学习训出来的分类模型有一个通病：极度狂妄。明明只有六七成把握，输出的概率非要顶到 99.9%。因为标准的策略梯度如果只拿 0 或 1 的胜负做 Reward，为了最大化收益，数学机制必然会逼着模型把最高分选项推向极端确定性。

但在自动化系统里，我们非常需要模型知道“自己不知道”。

在这个阶段，我们把模型扔进沙盒（扫雷、2048、黑白棋、浏览器环境），不用虚构的 Reward Model，而是用精确的动态规划解或蒙特卡洛采样，直接拿到候选动作在环境里的真实胜率分布。然后用严格评分规则（Proper Scoring Rules，如 Brier Loss）去监督判决头。在数学上，只有在完整分布监督下，策略梯度的不动点才会老老实实收敛到环境的真实概率。

这个训练带来的一个直观细节，是在面对随机性时的反应。

我们测过让几个主流大模型（DeepSeek、Qwen、Llama 等）去猜硬币的正反面，或者猜一枚十面骰子的点数。连测几十次，这些模型几乎 100% 顽固地预测硬币会落在“正面”，或者骰子点数是“7”——因为自回归模型的预训练语料里充满了这类偏好模式，它吐不出真正均匀的分布。而 Bongard 在面对抛硬币时，交出的输出是极其稳定的 `正面: 0.500, 反面: 0.500`；十面骰子的平均分布散度只有 0.0009。

最后是工程算力。

我们没有大集群，整个 Bongard 的全量 70.9 亿参数，是在**单张 NVIDIA Blackwell GPU** 上跑完的。三个阶段分别花了大约 51、23 和 11 个小时。

能在单卡上吃下 7B 全量后训练，靠的是几个比较极致的算子工程：

FFN 块全量采用 Transformer Engine 的 NVFP4 融合算子（在 8192 长度下比 FP8 快一倍多）；Attention 投影跑在行级缩放的 FP8 上；输入数据做无 Padding 的 Var-len 打包，靠 FlashAttention-4 的因果掩码一次性搞定 Self-attention 和 Cross-attention；优化器使用带随机舍入（Stochastic Rounding）的 8-bit AdamW，省掉全量 FP32 主副本的显存。

整个模型训完，我们在公共决策基准 DecisionBench（23,900 道决策题）上测出的准确率是 78.05%，排在 61 个系统里的第四位（前三名是榜单作者自己的模型和 Imajev-4B），越过了 GPT-5.6 Luna 和 DeepSeek V4.1 Flash。更重要的是，它的期望校准误差（ECE）是 0.063，远比闭源的 Jev（0.128）诚实。

关于名字：

之所以叫 Bongard，是因为米哈伊尔·邦加德（Mikhail Bongard）在 1960 年代设计的那些视觉谜题，是我在认知科学里最喜欢的一套思想实验。侯世达在《哥德尔、艾舍尔、巴赫》里花了大篇幅讨论它——两组图摆在面前，没有任何文字描述，人类却能一眼看出那条隐藏的分类界线。

Diogo 把他们的模型命名为 Jev（取自提出“杰文斯悖论”的经济学家 Jevons），视角落在了自动化降本引发的经济规模效应上；我更偏向从认知结构本身去看这个问题：机器的思考不应该被单一的字词序列绑架。

把非语言的直觉剥离出来，做成低延迟、高并发、概率自洽的基础组件，让自回归慢思考只在真正需要深思熟虑的地方介入，复杂的数字员工系统才有可能真正落地跑通。
